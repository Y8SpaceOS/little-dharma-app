# PR #135: Parent Weekly Summary v1

## PR title and purpose
PR #135: Parent Weekly Summary v1 adds a local-first, read-only weekly parent summary model and a minimal parent-facing dashboard card.

## Roadmap alignment
- Approved roadmap sequence shifted after PR #115–117 governance sprints.
- Original roadmap item PR #132 (Parent Weekly Summary v1) is implemented as PR #135.

## Why Parent Weekly Summary follows Mahabharata Journey Outline
PR #134 established the latest journey outline and metadata shape, so this summary can safely derive journeys touched and gentle next stories from runtime-safe journey references.

## Parent weekly summary goal
Help parents calmly understand stories completed, values explored, journeys touched, and one gentle next step.

## What this summary is
A local-only weekly digest generated on-device from existing completion and journey progress state.

## What this summary is not
No report card, no ranking, no pressure loop, no engagement tracking, and no cloud sync.

## Local-first data sources
- `src/lib/storyProgress.ts` read helpers.
- `src/lib/journeyProgress.ts` read helpers.
- `src/services/dharmaJourneyService.ts` for journey/story metadata.

## Weekly window rules
Default window is the last 7 days ending at generation time.

## Completed story rules
- Read existing completion entries only.
- Never mutate or prune completion state.
- Include only valid completion timestamps inside the weekly window.

## Values explored rules
- Derived from completion value words or journey/story value metadata.
- De-duplicated and human-readable.

## Journeys touched rules
Derived from completed stories and deduplicated by journey id.

## Reflection prompt rules
Reflection prompts are calm and value-oriented, with a gentle fallback prompt when no values were explored.

## Suggested next story rules
- Select from runtime-safe journey story refs only.
- Exclude non-runtime statuses and any unavailable/staged/outline-only paths.
- Prefer journeys already touched this week when possible.

## Empty state rules
When no stories were completed in the weekly window:
“No completed stories this week yet. You can continue gently whenever your family is ready.”

## Parent trust copy rules
Use local-first trust language, including “stored on this device.”

## Privacy/no-backend assumptions
No backend, auth, analytics, telemetry, email, push, sharing, or network APIs are added.

## No hard gamification rules
Do not introduce XP, coins, streaks, leaderboards, rank, score, performance framing, or report-card language.

## UI integration status
Integrated as a small read-only card on `app/(parent)/dashboard.tsx`.

## Relationship to Parent Journey Progress Dashboard v1
Weekly Summary v1 complements PR #128 by adding a time-bounded digest, while preserving local trust framing.

## Relationship to Story Completion Moment v1
Weekly Summary v1 reads completion outcomes generated by PR #129 without changing completion writes.

## Relationship to Runtime Story Resolver v2
Weekly summary recommendations rely on runtime-safe story references and do not bypass resolver/runtime eligibility constraints.

## What this PR changes
- Adds `src/services/parentWeeklySummaryService.ts`.
- Adds dashboard binding for a read-only parent summary card.
- Adds `scripts/validate-parent-weekly-summary-v1.mjs` and npm script.

## What this PR does not do
No backend sync, no accounts/login, no notifications, no sharing, no payments, no child route additions, and no Story World doorway ordering changes.
